## 一、高优先级缺陷

### H1. JSON 工具：折叠超长 JSON 导致渲染崩溃白屏 【已复现】

- **位置**：`src/tools/json/index.vue`（修复前 L52 + L58 + L66）
- **根因**：`folds` 基于**全部行**计算，而渲染只取前 5000 行（截断）。当某节点的起始行 < 5000、闭合行 > 5000 时，点击折叠按钮执行 `highlightJson(shown[close].trim())`，`shown[close]` 为 `undefined`，抛 TypeError，Vue 渲染崩溃。
- **复现**：粘贴 6000+ 行 JSON → 点击第 1 行折叠按钮 → 白屏。已用独立脚本复现确认。
- **严重度**：高（违反 PRD §5「任何非法输入不得白屏」与成功指标「0 起白屏」）。

### H2. JSON 工具：大输入 200ms 防抖为死代码

- **位置**：`src/tools/json/index.vue`（修复前 L43-47 vs L113-126）
- **根因**：技术设计 §12 要求「>100KB JSON debounce 200ms」；组件实现了 `effectiveInput`（200ms 防抖），但渲染链入口 `result` computed 直接消费 `input.value`，防抖被完全绕过——超过 100KB 时每次击键同步执行 lint + format + 高亮 5000+ 行，明显卡顿。

### H3. 二维码工具：「导出 PNG」缺失

- **位置**：`src/tools/qrcode/index.vue`
- **PRD 4.5.4** 明确「支持一键复制图片与**导出 PNG**」。实现只有「复制图片」，无任何导出能力（全项目无 `download`/`toBlob`）。

### H4. 颜色工具：「拾色器」缺失

- **位置**：`src/tools/color/index.vue`
- **PRD 4.6.1** 明确「颜色预览色块 + **拾色器**（点击弹出系统颜色选择）」。swatch 仅是预览 div，无 `<input type="color">`。且该工具在 plugin.json cmds 注册了「取色」关键词——用户搜「取色」进入后找不到取色功能。

### H5. Ctrl+Enter 复制主结果：13 个工具仅时间戳实现

- **PRD 4.2-2 通用规范**：所有工具「同时支持 Ctrl+Enter 复制主结果」。实际仅 `timestamp/index.vue` 实现，其余 12 个全部缺失。
- **次生问题**：timestamp 自身实现把 `@keydown` 绑在 `.tool-body` 上，而显示「Ctrl+Enter 复制」提示的 footer 在作用域外，焦点在 footer 复制按钮上时快捷键失效，与提示矛盾。

## 三、低优先级 / 体验一致性问题

1. **url-codec 参数表 `:key="k + v"`**：URL 含重复键值对（`?a=1&a=1`）时 key 冲突，Vue 渲染告警。
2. **hash 未防御 `services.hash` 缺失**：preload 加载失败时 `window.services || {}` 使 hash 为 undefined，`run()` 内同步 TypeError，`loading` 永久卡「计算中…」。
3. **router.js `currentTool` 用 `toolByCode[route.value]` 查 tool id**：当前 13 个工具 id===code 所以正常，属隐性约定，新增 id≠code 的工具即坏。
4. **base64 自动识别误伤普通词**：输入 `test`/`user` 等 4 字母词被判为 Base64 走解码 → 红字「解码失败」，需手动切编码。
5. **空态引导不统一**（PRD 4.2-5）：timestamp/radix/case-convert/color 有可点击示例；base64/url-codec/json/text-stat/date-calc 仅占位文字。
6. **date-calc 日期差区块**：结果不可复制、非法输入无红字提示（只显示「—」）、✕ 清空不回焦，与主面板行为不对称。
7. **HomeView「最近使用」行无收藏星标**：PRD 4.7.2「每个工具页面**与列表项**提供收藏开关」，最近使用区缺失。
8. **清空按钮回焦行为不统一**：date-calc ✕、case-convert ✕ 不回焦。
9. **timestamp 微秒输入时「毫秒级」hero 被标注「输入」**（修复前 L185 `res.unit !== '秒'`）：微秒输入时毫秒级是换算值不是输入原文，标注矛盾。
10. **date-calc 工作日天数**（PRD 4.4.1「可选输出工作日天数，排除周六日，P1」）未实现。
11. **技术设计 §4 `setExpandHeight`（JSON 大内容增高窗口）未实现**（测试清单已自曝「未被调用」）。
12. **哈希无「复制全部」**：四种摘要只能逐条复制。

## 四、工程质量问题

1. **4 个静态检查脚本未纳入 CI**：`check-imports.js`（防白屏的导入完整性检查——为修复一次白屏事故而生）、`check-payload-hooks.js`、`check-css-classes.js`、`check-match-regex.mjs` 只能手动跑，`npm run check` 与 CI 均不执行，防回归价值被浪费。
2. **check-css-classes.js 两处缺陷**：
   - 正则 `class="([^"]+)"` 会误匹配 `:class="{...}"` 中的 JS 对象内容，产生大量误报（`!favTools.length`、`&&` 等）；
   - 文件清单缺 6 个后补工具（hash/unicode/case-convert/text-stat/qrcode/color），qrcode 的死类 `qr-pane` 因此漏检。
3. **uuid `:key="u"`** 以值为 key，v4 碰撞概率≈0，理论可忽略，改索引更严谨。

## 六、正面评价（保持项）

- **架构**：`tools/index.js` 单一注册表 + `router.js` 状态路由 + `ToolShell` 统一骨架，新增工具成本符合 PRD「≤ 1 目录 + 1 行注册」约束。
- **可测性**：13 个纯函数模块与 UI 完全解耦，155 项单测覆盖验收标准（含 16 春节农历对拍、RFC 哈希向量、1MB JSON 性能）。
- **健壮性**：所有纯函数入口 `String(x ?? '')` 兜底；lint 校验器先于 `JSON.parse`；`Promise.allSettled` + seq 竞态守卫；UTF-8 fatal 解码；全链路不白屏。
- **安全**：单文件构建产物无网络请求依赖；v-html 内容全经 `esc()`；preload 最小暴露原则。
- **无障碍**：aria-label/aria-pressed/role=alert/aria-describedby 覆盖面好。
- **工程化**：三平台 CI 矩阵、dist 结构校验、plugin.json 合规校验、设计令牌约束。
