## 1. 运行环境与技术选型

### 1.1 运行环境（由 uTools Runtime 决定）

| 组件 | 版本 | 影响 |
| --- | --- | --- |
| Electron | 34.5.8 | 支持 `:400` CSS color-mix 等新特性，可用现代 CSS |
| Chromium | 132 | Vite 默认构建 target 即可，无需转译旧语法 |
| Node.js | 20.19.1 | preload 可用 `node:crypto`、`node:fs/promises` 等内置模块 |

### 1.2 选型决策记录

| 决策点 | 选择 | 理由 | 放弃的方案 |
| --- | --- | --- | --- |
| 框架 | Vue 3 + Vite | 沿用官方模板现状，团队熟悉 | React（迁移成本无收益） |
| 语言 | JavaScript（jsconfig 提示） | 项目体量小，引入 TS 收益有限 | TypeScript |
| UI 组件库 | 不引入，原生 CSS + 设计 token | 包体积与审核体验优先；工具界面简单 | Element Plus / Naive UI |
| 状态管理 | Vue 组合式函数（composables） | 无跨组件复杂状态，Pinia 过重 | Pinia |
| 哈希实现 | preload + `node:crypto` | 原生模块零依赖、性能好 | 纯 JS 实现（慢） |
| 农历算法 | 内置纯 JS 算法表（1900–2100） | 离线、可控、无依赖 | lunar-javascript（全功能但体积大） |
| 二维码 | `qrcode`（前端依赖，P1 时引入） | 成熟轻量、纯本地生成 | 调外部 API（违反本地计算原则） |
| 单元测试 | `vitest`（devDependency） | 与 Vite 原生集成，测纯函数足够 | Jest（配置成本高） |

## 2. 总体架构

### 2.1 三层架构（对齐官方架构图）

```
┌──────────────────────────────────────────────┐
│                前端界面层（Vue 3）              │
│                                              │
│  App.vue（路由分发）                           │
│  ├─ HomeView（工具导航 / 收藏 / 最近使用）        │
│  └─ tools/*/<ToolShell>（各工具页面）           │
│                                              │
│  utils/utools.js   ← 统一 API 入口（含 mock）   │
│  utils/db.js       ← 数据层（settings/fav/history）│
│  utils/clipboard.js← 复制 + toast              │
│  utils/convert/*   ← 纯函数转换逻辑（可单测）     │
└──────────────┬───────────────────────────────┘
               │ window.utools（uTools API）
               │ window.services（preload 桥接）
┌──────────────▼───────────────────────────────┐
│           preload 桥接层（CommonJS）            │
│  node:crypto → 哈希计算                        │
│  node:fs    → 历史记录文件读写                  │
│  （最小暴露，不透传原始 fs/path 对象）             │
└──────────────┬───────────────────────────────┘
               │
┌──────────────▼───────────────────────────────┐
│              uTools Runtime                    │
│  生命周期 / 同步数据库 / 本地数据目录 / 子输入框     │
└──────────────────────────────────────────────┘
```

### 2.2 运行环境探测与降级（浏览器开发模式）

`npm run dev` 可在普通浏览器中跑 UI（无 `window.utools`）。统一通过 `src/utils/utools.js` 访问宿主能力，内部自动探测环境并注入 mock：

```js
// src/utils/utools.js
const inUtools = typeof window !== 'undefined' && !!window.utools

export const utools = inUtools ? window.utools : (await import('./utools-mock.js')).default
export const services = inUtools ? window.services : (await import('./services-mock.js')).default
export const inUtoolsEnv = inUtools
```

- `utools-mock.js`：`onPluginEnter` 立即回调 `{ code: 'devtools-kit' }`，其余 API 空实现/内存实现；
- `services-mock.js`：哈希用 Web Crypto / 内存 Map 模拟历史存储；
- 所有业务代码**只 import 此模块**，禁止直接引用 `window.utools`，保证浏览器调试与 uTools 环境行为一致。

## 5. 前端路由设计

### 5.1 工具注册表（src/tools/index.js）

```js
import TimestampTool from './timestamp/index.vue'
// ...

export const CATEGORIES = [
  { id: 'codec',    name: '编解码与加密' },
  { id: 'datetime', name: '时间日期' },
  { id: 'text',     name: '文本与生成' },
  { id: 'design',   name: '设计辅助' },
]

export const tools = [
  {
    id: 'timestamp',                 // 内部唯一 id（数据库/历史使用）
    code: 'timestamp',               // plugin.json feature.code
    name: '时间戳转换',
    icon: '⏱',                       // 首版用字符 icon，M6 前替换为 svg
    category: 'codec',
    priority: 'P0',
    keywords: ['时间戳', 'unix', '毫秒', '日期转时间戳'],
    component: TimestampTool,
  },
  // ... 每个工具一项
]

export const toolById = Object.fromEntries(tools.map(t => [t.id, t]))
export const toolByCode = Object.fromEntries(tools.map(t => [t.code, t]))
```

> 插件主入口 `devtools-kit` 不在注册表中，作为特殊路由指向 HomeView。

### 5.2 路由状态与分发

路由即状态：`currentView: 'home' | toolId`，无 URL 路由（BrowserView 内无意义）。

```
onPluginEnter(action)
  ├─ code === 'devtools-kit' → currentView = 'home'，setSubInput(过滤)
  └─ code 命中 toolByCode    → currentView = tool.id，removeSubInput()
onPluginOut(isKill)
  └─ currentView = 'home'，filterKeyword = ''，removeSubInput()（复位，等待下次进入）
```

- App.vue 挂载时一次性注册 `onPluginReady` / `onPluginEnter` / `onPluginOut`（官方要求每类监听仅注册一次）；
- 主界面 ↔ 工具页的内部跳转不触发 `onPluginEnter`，直接改 `currentView` 并同步 SubInput 状态；
- 携带载荷进入（未来匹配指令）：`action.payload` 存入 `enterPayload`，工具组件通过 prop 消费（如时间戳工具直接预填）。

### 5.3 SubInput 联动流程

| 场景 | 动作 |
| --- | --- |
| 进入主界面 | `utools.setSubInput(onFilterChange, '搜索工具…', true)` |
| SubInput 输入变化 | `onFilterChange({ text })` → 更新 `filterKeyword` → HomeView 过滤 |
| 回车选中首个结果 | HomeView 监听 keydown Enter（SubInput 聚焦时回车事件由 `onSubInput` 无法捕获，改为 `setSubInputValue` 同步 + 主界面内 Enter 处理，M2 实测后定稿） |
| 进入工具页 | `utools.removeSubInput()`，焦点交给工具输入框 |
| 工具页返回主界面 | 重新 `setSubInput`（保留原关键词） |

> ⚠️ 风险项：SubInput 回车选中行为需在 M2 阶段用开发者工具实测验证（不同 uTools 版本对 SubInput Enter 的处理可能不同），如有出入以「主界面内置搜索框兜底」方案降级：即 HomeView 顶部自带搜索输入框，SubInput 仅做占位。

### 6.2 通用 composables

| 函数 | 文件 | 说明 |
| --- | --- | --- |
| `useCopy()` | utils/clipboard.js | `copyWithToast(text, label)`：utools.copyText + Toast「已复制」 |
| `useFavorite(toolId)` | utils/db.js | `isFav / toggleFav`，读写 dbStorage |

### 6.3 纯函数与 UI 分离

`utils/convert/*.js` 一律为无副作用的纯函数，签名约定：

```js

export function convert(input, options) { /* ... */ }
```

工具组件只负责：读取输入 → 调用纯函数 → 渲染 `data` 或 `error`。所有边界判断在纯函数内完成，保证可单测。

## 7. preload 桥接层设计（public/preload.js）

遵循官方规范：CommonJS、`window.services` 命名空间、最小暴露、禁止透传 fs/path 原始对象。

```js
const { createHash } = require('node:crypto')
const fs = require('node:fs')
const path = require('node:path')

// ---- 历史记录文件（本地数据目录，不入同步库）----
const historyFile = () => path.join(utools.getPluginLocalDataPath(), 'history.json')

function readHistory() {
  try {
    return JSON.parse(fs.readFileSync(historyFile(), 'utf-8'))
  } catch { return { version: 1, history: {} } }
}
function writeHistory(data) {
  fs.mkdirSync(utools.getPluginLocalDataPath(), { recursive: true })
  fs.writeFileSync(historyFile(), JSON.stringify(data), 'utf-8')
}

window.services = {
  // P1：哈希计算（node:crypto，支持 md5/sha1/sha256/sha512）
  hash: (text, algo) => createHash(algo).update(text, 'utf-8').digest('hex'),

  // 历史记录（P1）
  historyRead: () => readHistory(),
  historyWrite: (data) => { writeHistory(data); return true },
}
```

约束与说明：

- 接口粒度为「业务动作」而非「文件操作」，前端不接触路径与 fs；
- `getPluginLocalDataPath()` 目录不存在时官方保证自动创建，仍防御性 `mkdirSync`；
- preload 不经 Vite 构建，保持零 npm 依赖（仅 node 内置模块）；
- dev 模式下该文件被 uTools 直接从 public/ 加载，改动后需重进插件。

## 8. 数据层设计（src/utils/db.js）

### 8.1 分存储介质（对齐官方《数据存储》分类）

| 数据 | 介质 | 原因 |
| --- | --- | --- |
| 设置（theme） | `dbStorage` | 用户配置，官方建议同步库；键值 API 足够简单 |
| 收藏（favorites） | `dbStorage` | 用户数据，多设备同步有价值 |
| 历史记录（history） | 本地数据目录 JSON 文件（经 preload） | 官方明确「操作记录」不入同步库，且写入频率高 |

### 8.2 Schema

```js
// dbStorage 键值（自动 JSON 序列化）
'devtools-kit:settings'  → { theme: 'auto' }            // 'auto' | 'light' | 'dark'
'devtools-kit:favorites' → ['timestamp', 'base64']      // 工具 id 数组

// history.json（本地数据目录）
{
  "version": 1,
  "history": {
    "timestamp": [
      { "input": "1735689600000", "output": "2025-01-01 08:00:00", "ts": 1735689600000 }
    ]
  }
}
```

### 8.3 API 与行为约定

```js
// utils/db.js
getSettings() / saveSettings(patch)
getFavorites() / toggleFavorite(toolId)      // 返回新数组
getRecentTools(limit = 10)                   // 合并历史时间戳推导「最近使用」
addHistory(toolId, input, output)            // 与末条重复则跳过；>50 条 LRU 淘汰
removeHistory(toolId, index) / clearHistory(toolId | 'all')
```

- **记录时机**：工具产出有效结果后，输入停止变化 **1 秒**（debounce）时写入，避免高频写盘；
- **失败降级**：所有读写 try/catch，失败静默（历史/收藏属增强功能，不得影响主流程）；
- **版本迁移**：history.json 带 `version` 字段，未来结构变更时按版本号迁移。

- **规范文档**：[`docs/设计令牌.md`](./设计令牌.md)（目录、场景约束、对比度红线、治理与变更流程）。

要点摘要（细节以规范为准）：

- 双层架构：**语义层**（颜色，随 `html[data-theme]` 切换）+ **组件层**（字号/间距/圆角/动效/尺寸/层级，主题无关）；原始色值仅登记在规范色板表，不进代码；
- 组件样式**禁止硬编码**视觉值与暗色主题选择器；品牌蓝 `--accent` 仅用于焦点环/指示条/弱底，文字一律 `--accent-text`（白底 3.76:1 不达标）；
- 对比度红线：文本 ≥ 4.5:1（WCAG 1.4.3）、控件边界 ≥ 3:1（WCAG 1.4.11）——`--muted`、`--danger`、`--border-control`、`--accent-text` 均按此校准，登记于规范 §9；
- 字体为系统栈（`--ui` / `--mono`），禁网络字体；字号全站 5 档（12/13/14/16/20），间距 10 档（2–24px）；动效仅 `80ms/150ms` 两档并遵循 `prefers-reduced-motion` 降级。

### 9.2 主题切换机制

```
settings.theme = 'auto' (默认) | 'light' | 'dark'
auto → 跟随 matchMedia('(prefers-color-scheme: dark)')（官方推荐）
       并监听 change 事件实时切换
最终结果写入 document.documentElement.dataset.theme
```

> 放弃 `utools.isDarkColors()`：官方文档明确推荐插件界面主题判断使用 `prefers-color-scheme`，且媒体查询自带变更监听，无需轮询。

## 11. P0 工具实现要点

### 11.1 时间戳转换（utils/convert/timestamp.js）

- **方向自动识别（v0.2 定稿，原型验证）**：单输入框，纯数字 → 时间戳；含日期分隔符（`-` `/` `:` 空格 `T`、年月日）→ 日期。不做显式模式切换——与「输入即转换」（PRD 4.2-1）及匹配指令携载进入（粘贴即转换）的产品形态一致；
- **单位识别按数量级阈值，不限位数（PRD 4.3.1 v0.3）**：
  - `n < 1e11` → 秒（覆盖 10 位常见形态，含 `0` 与更短输入）；
  - `1e11 ≤ n < 1e14` → 毫秒（覆盖 13 位）；
  - `1e14 ≤ n < 1e18` → 微秒，÷1000（四舍五入）转毫秒并标注「识别为微秒」；
  - `n ≥ 1e18` → 报「超出可表示时间范围」（Date 上限 ±8.64e15 ms，即 ±100,000,000 天）；
  - 依据：PRD 旧版「输入 0 → 1970-01-01 08:00:00」验收项与「仅 10/13 位，其余报错」功能要求自相矛盾，v0.3 统一为数量级规则；识别结果经输入框后缀标签透明展示（「10 位 · 秒」「16 位 · 微秒」），单位判断始终可见；
- **日期解析**：显式正则匹配 `YYYY-MM-DD[ HH:mm[:ss]]`、`YYYY/MM/DD[ HH:mm[:ss]]`、`YYYY-MM-DD`、ISO 8601（含时区）；解析结果逐字段回读校验（`2025-02-30` 类输入报错不进位），禁用 `new Date(str)` 隐式解析的歧义；
- **输出**：秒级 / 毫秒级 / 本地时间 / UTC / ISO 8601 / 星期 / 相对时间（30s 随时钟刷新），来源方向项标「输入」；时区标注 `Intl.DateTimeFormat().resolvedOptions().timeZone` + `getTimezoneOffset()`；
- **当前时间戳**：底部状态条实时刷新（秒 + 毫秒各带复制按钮），`setInterval(1000)`，`onUnmounted` 清理；

### 11.2 日期换算（utils/convert/dateCalc.js）

- **农历（v0.4 方案变更：IntL 中文历法替代查表法）**：基于运行环境内置的中文历法 `Intl.DateTimeFormat('zh-CN-u-ca-chinese')`——uTools Runtime（Chromium 132 / 全量 ICU）三平台内置，零数据表维护、零手写算法出错风险，原型已在真实环境验证；输出农历月日、天干地支年（`formatToParts` 的 `yearName`）与生肖（地支→生肖固定映射）；**决策依据**：手写 1900–2100 查表数据无法离线验证全量正确性，ICU 为官方实现；范围边界跟随 ICU（约 1900–2100，与原设计一致），组件层对范围外输入报「超出支持范围」；
- **ISO 周数**：按 ISO 8601 标准（周四属周）计算，跨年周归属年份一并返回；
- **日期差**：两日期均取 **UTC 12:00** 计算差值天数，规避夏令时导致的 ±1 天误差；
- **「今天」快捷按钮**一键填入当前日期。

### 11.3 Base64（utils/convert/base64.js）

- 编码：`TextEncoder` → 字节 → 分块 `btoa`（每 0x8000 字节分块拼接，规避 call stack 限制），天然支持中文/Emoji；
- 解码：归一化（`-`→`+`、`_`→`/`、补 `=` padding）→ 校验 `/^[A-Za-z0-9+/]*={0,2}$/` 与长度合法性 → `atob` → `TextDecoder('utf-8')`；
- 模式自动检测：输入命中 Base64 字符集且长度 %4===0 时默认解码模式，用户可手动锁定编码/解码。

### 11.4 URL 编解码（utils/convert/urlCodec.js）

- 编码双模式：`encodeURIComponent`（默认）/ `encodeURI`，切换即时重算；
- 解码：`decodeURIComponent`，try/catch 捕获 `URIError` → 报「非法 % 转义序列」；
- URL 结构化解析：`new URL()` + `URLSearchParams` 生成参数键值表；解析失败按纯文本处理（只做编解码）。

### 11.5 JSON 格式化（utils/convert/jsonFormat.js）

- 校验定位：**自写轻量 JSON 校验器（状态机 lint，v0.2 定稿）**，逐字符扫描直接产出 `行:列 + 原因 + 出错位置`，**不依赖 V8 `SyntaxError` 文案**——当前 Chromium 对部分语法错误不再附带 position 信息（原型已验证该缺口）；lint 通过后再 `JSON.parse` 取值（此时不会失败），`stringify` 按 2/4 空格 / Tab / 压缩输出；lint 的行列正确性纳入单测（§13）；
- 高亮：自研轻量 tokenizer（单正则逐 token 染色：key/string/number/boolean/null/标点，约 60 行），**不引入** highlight.js（体积）；
- 折叠：按行渲染 + 「折叠区间」数组方案（记录每行缩进层级，折叠时隐藏子级行），支持展开/收起全部；
- 大内容策略：输入 > 100KB 时 debounce 200ms；输出 > 5000 行时仅渲染前 5000 行并提示「内容过长，已截断显示（不影响复制完整结果）」（复制始终用原始字符串）——规避首版虚拟滚动的复杂度，Q2 就此闭环，M3 实测后如体验不佳再升虚拟滚动。

### 11.6 进制转换（utils/convert/radix.js）

- 统一用 `BigInt` 计算，规避 `>2^53-1` 精度丢失；
- 输入自动识别前缀 `0b`/`0o`/`0x`；按所选输入进制 `/^[0-7]+$/` 等逐进制校验字符集；
- 输出 2/8/10/16 进制 + 只读 36 进制；`BigInt.prototype.toString(radix)` 原生支持；
- 当输入为 10 进制且绝对值 > `Number.MAX_SAFE_INTEGER` 时展示精度告警（实际无精度损失，仅提示该值超出常规 JS 安全整数，供用户知悉）。

### 11.7 UUID 生成（utils/convert/uuid.js）

- `crypto.getRandomValues()` 实现标准 RFC 4122 v4（版本位/变体位设置）；
- 批量上限 100，格式切换（标准/无连字符/大写）用正则后处理；
- 唯一性由随机源保证，不做去重检查（128bit 碰撞概率可忽略），单测验证格式正则与版本位正确性。

## 12. 错误处理与性能约定

| 层 | 策略 |
| --- | --- |
| 纯函数层 | 一切非法输入返回 `{ ok: false, error }`，不抛异常 |
| 组件层 | 行内错误展示；`app.config.errorHandler` 兜底捕获渲染异常 → Toast 提示 + console |
| preload 层 | 文件读写 try/catch，失败返回空结构 |
| 性能 | 输入即转换不加防抖（<100KB）；>100KB JSON debounce 200ms；输出渲染截断 5000 行；定时器组件卸载必清理 |
