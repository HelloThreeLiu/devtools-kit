## 1. 约束力（治理规则）

1. **唯一来源**：所有 UI 相关的颜色、字号、间距、圆角、动效、尺寸、层级值，只允许以 `docs/design/tokens.css` 中的令牌形式存在。组件样式（Vue 组件 / main.css）**禁止硬编码**这些值。
2. **先登记后使用**：新增或修改令牌，必须先更新本文件的目录表与色板参考（含对比度验证），再修改 `tokens.css`，最后才允许在组件中引用。禁止「组件里先写死、回头再收令牌」。
3. **对比度红线**：文本对比度 ≥ 4.5:1（WCAG 1.4.3）；控件边界等非文本对比度 ≥ 3:1（WCAG 1.4.11）。任何不达标的新色值不得登记。
4. **主题无关原则**：组件样式只引用语义令牌，**禁止**在组件内出现 `html[data-theme="dark"]` 选择器（暗色适配全部由 tokens.css 的语义层完成）。
5. **审查口径**：M5 验收与代码 review 时，凡 UI 变更先查「值是否来自令牌」，再查「令牌使用场景是否符合本规范」。

## 2. 设计基调

**精密仪表风**：数据区域一律等宽字体（`--mono`）、细边框分区、克制的品牌色（仅焦点环 / 指示条 / 弱底）、密集但透气的信息排布。界面是工具，不是海报——不做装饰性渐变、插画与大圆角。

画布基准：**800 × 544**（uTools 插件应用区域，`pluginSetting.height` 默认值，不含主输入框）。主界面必须在此画布内一屏可见、无滚动。

## 3. 令牌架构

```
色板参考表（原始值，仅登记在本规范 §8，不进代码）
        ↓ 映射
语义层（颜色）：随主题切换，组件只认识这一层
        ↓ 引用
组件层（字号/间距/圆角/动效/尺寸/层级）：主题无关，恒定
```

- 颜色一律走语义层：组件中写 `var(--muted)`，永远不写 `#5d6772`；
- 引入第三层（原始层进代码）的门槛：同一原始色被 ≥ 3 个语义令牌复用时再评估，当前规模不需要。

## 5. 字体与字号

### 5.1 字族（系统栈，禁止网络字体——插件无网络请求）

| 令牌 | 栈 | 用途 |
| --- | --- | --- |
| `--ui` | `"Segoe UI", "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", "Helvetica Neue", Arial, sans-serif` | 界面文本默认 |
| `--mono` | `"JetBrains Mono", "Cascadia Code", Consolas, "SF Mono", Menlo, "Courier New", monospace` | **一切数据**：输入值、结果值、时间戳、指令名、行号、kbd |

规则：凡是「用户将复制出去的内容」和数字，一律 `--mono` + `tabular-nums`；说明性中文用 `--ui`。

### 5.2 字号（全站 5 档，禁止其他值）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--fs-12` | 12px | 区块标签、状态栏、行号、键名、tag |
| `--fs-13` | 13px | 按钮、输入框、错误文案、菜单项、示例 |
| `--fs-14` | 14px | body 默认、工具行名称、hero 旁注 |
| `--fs-16` | 16px | 工具页标题、空态标题 |
| `--fs-20` | 20px | 主结果 hero 数字（配 `--fw-medium`） |

字重仅三档：`--fw-regular: 400` / `--fw-medium: 500` / `--fw-semibold: 600`。

### 5.3 行高

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--lh-tight` | 1.3 | hero 大数字、标题 |
| `--lh-normal` | 1.5 | 默认正文 |
| `--lh-mono` | 1.65 | 多行等宽文本（textarea、代码区） |

单行控件（按钮/输入/行）`line-height: 1`，随控件高度居中。

## 6. 间距 · 圆角 · 动效

### 6.1 间距（唯一刻度，命名即像素）

`--sp-2` `--sp-4` `--sp-6` `--sp-8` `--sp-10` `--sp-12` `--sp-14` `--sp-16` `--sp-20` `--sp-24`

规则：margin / padding / gap 只能取以上刻度；页面左右留白统一 `--gutter`（24px）；工具页纵向区块间距 `--sp-16`；面板内边距基准 `--sp-14`。

### 6.2 圆角

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--radius-sm` | 4px | kbd、tag、行内小按钮、折叠开关 |
| `--radius` | 6px | 默认：按钮、输入框、工具行 |
| `--radius-lg` | 8px | 面板、浮层、textarea、toast |

### 6.3 动效

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--dur-fast` | 80ms | hover / press / 颜色过渡 |
| `--dur` | 150ms | 浮层、toast 进出 |
| `--ease` | `cubic-bezier(0.2, 0, 0, 1)` | 统一缓动 |

规则：只允许过渡 `opacity / transform / box-shadow / color / background-color / border-color`；禁用位移入场动画；`prefers-reduced-motion` 降级已内置于 tokens.css。**转换计算本身禁止加动画**（PRD 4.2-1：输入即转换 ≤ 100ms）。

## 7. 尺寸 · 层级 · 图标

### 7.1 布局与控件尺寸（M2 起强制引用令牌）

| 类别 | 令牌与值 |
| --- | --- |
| 画布 | `--canvas-w: 800px` · `--canvas-h: 544px` |
| 页面骨架 | `--gutter: 24px` · `--h-topbar: 48px` · `--h-tabs: 46px` · `--h-statusbar: 34px` · `--h-statusbar-live: 42px` |
| 控件高度 | `--h-control: 30px`（按钮/图标按钮/返回）· `--h-control-sm: 26px`（分段选项、面板内图标按钮）· `--h-control-xs: 24px`（行内操作、输入清除） |
| 输入 | `--h-input: 42px`（textarea 最小高 72px，用 `--sp-*` 内边距） |
| 行 | `--h-row: 38px`（工具行）· `--h-row-sm: 34px`（快捷行/菜单项） |
| 小件 | `--h-tag: 20px` · `--h-kbd: 20px` · `--h-toast: 34px` |
| 网格列 | `--section-label-w: 72px`（主界面标签列）· `--kv-label-w: 88px`（结果面板键列） |

工具行双列网格：`grid-template-columns: repeat(2, minmax(0, 1fr))`，列距 `--sp-8`、行距 `--sp-4`。

### 7.2 层级

`--z-lineno: 1`（JSON 行号 sticky）· `--z-menu: 30`（浮层）· `--z-toast: 90`（轻提示）。禁止其他 z-index 值。

### 7.3 图标（单线 SVG）

- 24 网格绘制、`stroke: currentColor`、`fill: none`、圆角端点，命名 `#i-*` 收录于原型 proto.js 图标表；
- 尺寸档：默认 20px（stroke 2）/ `--sm` 16px（stroke 2.25）/ `--xs` 12px（stroke 2.6）/ `--lg` 24px（stroke 2）；
- 图标默认色 `--muted`，交互态转 `--fg`；语义色仅在状态语义成立时使用（成功 ✓ 用 `--success`）；
- **禁止 emoji 与文字徽标替代图标**（原型评审已定稿）。

## 10. 用法规则（Do / Don't 速查）

**必须**
- ✅ 数据、数字、可复制内容用 `--mono` + `tabular-nums`；
- ✅ 品牌色文字用 `--accent-text`；
- ✅ 输入框三态边框走 §4.2 的状态链；
- ✅ 新组件先在本规范找令牌，找不到再走 §11 流程。

**禁止**
- ❌ 组件内硬编码任何色值 / 字号 / 间距 / z-index；
- ❌ 组件内写暗色主题选择器（主题适配只在 tokens.css）；
- ❌ `--accent` 作小字号文字；
- ❌ emoji / 文字徽标当图标；
- ❌ 网络字体、装饰性渐变、大阴影、位移入场动画；
- ❌ 转换计算加过渡动画（性能红线 ≤ 100ms）。

## 11. 令牌变更流程

1. 提案：在本文件修订记录新增条目，说明动机（对比度不达标 / 新组件需求）；
2. 验证：颜色类必须给出新旧值在两类背景上的对比度计算；尺寸/字号类必须说明为何现有档位不满足；
3. 落地：修改 `docs/design/tokens.css`（同一提交内）；
4. 评审：随 PRD / 技术设计评审一起确认；
5. 同步：审阅台原型 `proto.css` 的 `:root` 区块与 tokens.css 保持一致（值级同步，提交前 diff 核对）。

## 12. 落地映射

| 阶段 | 动作 |
| --- | --- |
| 现在（原型阶段） | `tokens.css` 与 `proto.css :root` 值级一致；原型组件层暂存等值硬编码（已逐项核对，见 §7 表格） |
| M2 架构搭建 | `tokens.css` 全文并入 `src/main.css` 基础层；组件样式全部改为引用令牌（含把原型的等值硬编码替换为令牌引用） |
| 后续迭代 | 任何 UI 改动按 §1 治理规则与 §11 流程执行 |
