    评审要点

      开发工具箱

      uTools 主窗口模拟：上方是主输入框，下方是 800 × 544 的插件区域。主界面下可直接在输入框里过滤工具，按 ↓ 进入列表、按 Enter 打开首个匹配。数字键 1–5 切换页面。

      设计说明与待确认事项

      已定事项（2026-11-25 评审结论，写入 PRD v0.3 / 技术设计 v0.2）

      • PRD 4.3.1 矛盾：修订为数量级阈值识别，不限位数——< 10¹¹ 秒、10¹¹–10¹⁴ 毫秒、10¹⁴–10¹⁸ 微秒（÷1000）、≥ 10¹⁸ 超范围报错。输入 0 → 1970-01-01 08:00:00 成立；原型原「仅 10/13 位」实现已按新规则调整（5 位 12345 现按秒识别为 1970-01-01 08:20:45，后缀标签透明标注单位）。
      • API 名：核实为 setExpandHeight——utools-api-types 8.x 定义 setExpandHeight(height): boolean，与现行官方文档一致；setExpendHeight 是旧版本的拼写，不采用。本审阅台此前注记有误。
      • 时间戳自动方向：定稿保留，不恢复显式模式切换（与「输入即转换」及匹配指令携载进入的形态一致）。
      • 历史记录入口（PRD 4.7.1）：工具页头部「历史」下拉面板——点击记录回填输入、单条 ✕ 删除、面板底部「清空本工具」；主界面「最近使用」标题右侧提供「清空全部历史」（二次确认）。原型待补，实现以 PRD v0.3 为准。
      • JSON 定位：页面内自写校验器方案定稿为正式实现方案（技术设计 §11.5 v0.2），不依赖 V8 报错文案，配套单测覆盖行列正确性。
      • 画布语义：544 = 插件应用自身高度（pluginSetting.height），不含主输入框，页面按 800 × 544 设计，定稿。

      画布与主输入栏

      • 页面按 800 × 544 设计。官方文档中 pluginSetting.height 默认值 544、setExpandHeight 的说明是「设置插件应用在主窗口中的高度」，所以 544 是插件应用自身的高度，不含上方的主输入框。旧原型把 544 当成了含输入栏的总高，页面实际只按 500 设计。
      • 主界面调用 setSubInput(onChange, placeholder, isFocus) 后，uTools 主输入框就是搜索框，页面内不再放第二个搜索框。上方主输入栏的结构参照官方文档的效果图。
      • 进入工具页后 removeSubInput()，主输入栏交还 uTools，所以工具页上方显示为不可输入。
      • 子输入框里的回车、方向键能否被插件接收到，仍是技术设计里的风险项 T1，这里演示的是期望行为。

      相对旧原型的改动

      • 图标全部换成同一套单线 SVG（24 网格、统一描边），不再使用 emoji 和文字徽标。
      • 主界面改为「左标签列 + 内容列」：收藏、最近使用各占一行，13 个工具两列排布，800 × 544 内一屏可见，无需滚动。
      • 工具页去掉卡片套卡片：一个输入框加一个结果面板，结果用「键 | 值」行承载。
      • 时间戳页取消模式切换：输入时间戳或日期自动识别方向，并同时给出秒、毫秒、本地、UTC、ISO 与相对时间。
      • JSON 页补上了 PRD 4.3.4 要求的节点折叠，输出格式用一组分段控件切换（2 空格 / 4 空格 / Tab / 压缩）。
      • 外观设置按 PRD 4.7.3 提供「跟随系统 / 亮色 / 暗色」三选项，入口在主界面右上角。

      设计 token（与 §9.1 v0.2 已同步，此处保留调整依据）

      • --muted 由 #6a737d 调深为 #5d6772：原值在浅灰和选中底色上只有 4.2–4.4:1。
      • --danger 文字色由 #e5484d 调为 #ba2126：原值在白底上只有 3.9:1；原值保留为 --danger-fill。
      • 新增 --accent-text（#0b5fd0）：品牌蓝 #1e80ff 做文字只有 3.76:1，只用于焦点环和选中指示条。
      • 新增 --border-control：输入框边框对白底达到 3:1（WCAG 1.4.11）。

      原型里的演示数据

      • 「我的收藏」「最近使用」的初始内容和时间均为演示数据；在原型里打开某个工具页，会把它记入最近使用。
      • 农历由运行环境内置的中文历法算出，是真实结果；正式版按技术设计 §11.2 内置查表算法。
      • JSON 的行号、列号由页面内自写的校验器给出：当前 Chromium 对部分语法错误不再在报错文案里附带位置。
