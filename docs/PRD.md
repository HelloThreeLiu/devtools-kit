## 1. 产品概述

### 1.1 背景与问题

开发者在日常工作中频繁进行碎片化的小工具操作：时间戳与日期互转、Base64/URL 编解码、JSON 格式化、进制转换、颜色值换算等。现有方案存在以下痛点：

- **切换成本高**：临时打开网页工具或独立软件，打断工作心流；
- **质量参差**：在线工具夹带广告、弹窗，甚至存在数据外泄风险；
- **入口分散**：不同工具散落在不同网站，无统一入口和记忆。

uTools 的「呼起即用、用完即走」产品形态天然适合承载这类高频小工具。本插件旨在提供一个**本地化、无广告、统一入口**的开发者工具箱。

### 1.2 产品定位

一句话定位：**面向开发者的 uTools 一站式开发工具箱，聚合高频开发辅助小工具，搜索直达、本地计算、数据不出本机。**

核心原则：

1. **快**：呼起 → 输入 → 出结果 → 复制，全程键盘优先，无多余点击；
2. **纯本地**：所有转换计算在本地完成，不上传任何用户数据；
3. **免费用**：首版不涉及支付与会员能力。

### 1.3 目标用户

**主要用户**：开发者（前端 / 后端 / 测试 / 运维），特征：

- 每天多次进行编码转换、格式化、调试辅助操作；
- 熟悉专业术语（时间戳、Base64、HEX 等），无需新手引导；
- 习惯键盘操作，追求效率，反感广告干扰。

**次要用户**：产品 / 设计等泛技术岗位，偶尔使用进制换算、颜色转换、二维码生成等工具。

### 1.4 竞品参考

uTools 插件市场已有同类插件（如「工具集」「快捷开发工具」等）。本产品的差异化策略：

- 工具分类清晰、首版聚焦高频工具，不做大而全；
- 全部本地计算，无联网依赖（二维码、农历等纯算法实现）；
- 输入即转换 + 一键复制，交互零负担。

## 3. 用户场景与核心用户故事

**场景 A — 排查接口问题**：后端拿到日志里的 `1735689600000`（13 位毫秒时间戳），呼起 uTools 输入时间戳直达转换，立即得到可读时间并反推。

**场景 B — 调试接口返回**：前端从接口复制一段压缩 JSON，呼起插件格式化并校验合法性，定位字段后复制。

**场景 C — 快速生成测试数据**：测试人员需要批量生成 UUID 作为主键，呼起插件一键生成 20 个并复制。

**场景 D — 前端取色换算**：设计师给了一个 `#1E80FF`，前端需要 RGB 值写代码，呼起插件粘贴即得。

核心用户故事（每工具的详细验收标准见第 4 章）：

- 作为开发者，我想要把时间戳和日期时间双向转换，以便快速排查时间相关问题；
- 作为开发者，我想要粘贴一段 Base64/URL 编码文本立即解码，以便调试传输数据；
- 作为开发者，我想要格式化并校验 JSON，以便阅读和定位接口报文；
- 作为开发者，我想要在工具箱主界面快速找到并收藏常用工具，以便减少搜索步骤。

### 4.2 通用交互规范（适用于所有工具）

所有工具页面必须遵循以下统一规范（作为验收标准的一部分，后文不再重复）：

1. **输入即转换**：输入内容变化后 ≤ 100ms 内完成结果计算，无需点击「转换」按钮；
2. **一键复制**：每个结果区域提供复制按钮，点击后使用 `utools.copyText()` 复制并出现「已复制」轻提示；同时支持 `Ctrl+Enter` 复制主结果；
3. **粘贴即用**：呼起工具后焦点自动落在主输入框，支持 `Ctrl+V` 直接粘贴；
4. **输入容错**：非法输入时给出明确的行内错误提示（红字 + 原因），不得白屏或卡死；
5. **空态引导**：无输入时展示一句用法示例，如「输入时间戳或日期，如 1735689600 / 2025-01-01 08:00:00」；
6. **即时清除**：提供「清空」操作，一键回到空态；
7. **返回导航**：工具页头部提供「← 返回」按钮回到工具列表（主界面）；不拦截 `Esc` 等由 uTools 全局处理的快捷键，避免与宿主行为冲突。

### 4.3 编解码与加密类

#### 4.3.1 时间戳转换（P0）

**用户故事**：作为开发者，我想要在时间戳与日期时间之间双向转换，以便快速排查日志和接口中的时间问题。

**功能要求**：

- 支持输入 10 位（秒）与 13 位（毫秒）时间戳，自动识别位数；其他位数给出明确报错；
- 支持 16 位微秒级时间戳识别并提示（P2 可选支持完整转换）；
- 输出展示：本地时间、UTC 时间、ISO 8601 格式、相对描述（如「3 天前」）、对应星期；
- 反向转换：输入日期时间字符串（支持 `YYYY-MM-DD HH:mm:ss`、`YYYY/MM/DD`、ISO 8601 等 3 种以上常见格式），输出秒级与毫秒级时间戳；
- 实时显示「当前时间戳」（秒与毫秒），每秒刷新，可一键复制；
- 时区说明：所有展示基于本机时区，页面注明当前时区（如 UTC+8）。

**验收标准**：

- 输入 `0` 输出 `1970-01-01 08:00:00`（东八区环境）；
- 输入 `1735689600000`（13 位）与 `1735689600`（10 位）输出同一时刻；
- 输入 `2025-01-01 08:00:00` 输出秒级 `1735689600`；
- 输入 `abc`、`12345`（5 位）等非法内容时显示错误提示，不输出错误结果；
- 当前时间戳每秒刷新且偏差 ≤ 1 秒。

#### 4.3.2 Base64 编解码（P0）

**用户故事**：作为开发者，我想要对文本进行 Base64 编码与解码，以便调试 HTTP Basic 认证、JWT 片段等传输内容。

**功能要求**：

- 编码模式：输入任意 UTF-8 文本，输出标准 Base64（含 padding）；
- 解码模式：输入 Base64 文本，输出 UTF-8 文本；自动检测模式（输入含 Base64 字符集特征默认解码，可手动切换）；
- 支持 URL-Safe 变体（`-`/`_`）的解码容错；
- 非法 Base64（含非法字符、长度错误）报错并提示原因。

**验收标准**：

- `hello` → `aGVsbG8=`；`aGVsbG8=` → `hello`；
- 中文「你好」→ `5L2g5aW9`，且可正确解码还原；
- URL-Safe 输入 `5L2g5aW9`（无 padding）可解码成功；
- 输入 `ab!c` 报错「包含非法字符」。

#### 4.3.3 URL 编解码（P0）

**用户故事**：作为开发者，我想要对 URL 或查询参数进行编码/解码，以便调试 GET 请求与回调地址。

**功能要求**：

- 支持 `encodeURI` 与 `encodeURIComponent` 两种编码模式（切换选择，默认后者）；
- 解码输出 `%XX` 序列还原后的 UTF-8 文本；
- 解析完整 URL 时额外展示结构化信息：协议、主机、端口、路径、各查询参数键值表。

**验收标准**：

- `https://a.com/?kw=你好` 编码后 `kw` 参数为 `%E4%BD%A0%E5%A5%BD`；
- 解码 `%E4%BD%A0%E5%A5%BD` 得到「你好」；
- 粘贴完整 URL 时正确展示参数表格；非法 `%` 序列报错不崩溃。

#### 4.3.4 JSON 格式化/校验（P0）

**用户故事**：作为开发者，我想要格式化、压缩并校验 JSON，以便阅读接口报文并快速定位语法错误。

**功能要求**：

- 格式化：2 空格缩进输出（可切换 4 空格 / Tab）；支持压缩为一行；
- 校验失败时给出错误位置（行号 + 列号）与原因；
- 语法高亮渲染；节点可折叠/展开；
- 支持从剪贴板快速粘贴（呼起即聚焦）。

**验收标准**：

- 1MB 以内 JSON 格式化耗时 ≤ 1 秒，界面不卡死；
- 输入 `{"a":1,}` 报错并定位到出错行列；
- 嵌套对象折叠/展开正常；压缩结果为合法单行 JSON。

#### 4.3.5 进制转换（P0）

**用户故事**：作为开发者，我想要在 2/8/10/16 进制之间互转，以便处理位运算、内存地址、协议字段等问题。

**功能要求**：

- 支持输入 2/8/10/16 进制整数，同时输出其余全部进制结果；
- 自动识别前缀：`0b`/`0o`/`0x`；
- 支持 36 进制展示（只读输出）；
- 超过安全整数范围（±2^53-1）时提示精度风险；
- 支持负数。

**验收标准**：

- 输入 `255` → 二进制 `11111111`、八进制 `377`、十六进制 `ff`（十六进制大小写统一小写展示）；
- 输入 `0xff` 自动按 16 进制处理；
- 输入 `9007199254740993` 显示精度告警；
- 非法字符（如二进制中输入 `2`）报错。

#### 4.3.6 哈希计算（P1）

**用户故事**：作为开发者，我想要计算文本的 MD5/SHA 系列哈希，以便校验数据一致性与生成摘要。

**功能要求**：

- 支持 MD5、SHA-1、SHA-256、SHA-512 四种算法，一次性并行输出全部结果；
- 输入编码按 UTF-8 处理；支持大小写展示切换（默认小写）。

**验收标准**：`abc` 的 SHA-256 结果为 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`；四种算法结果均可被第三方工具交叉验证。

#### 4.3.7 Unicode 转中文（P1）

**功能要求**：支持 `\uXXXX` 转义序列与中文互转；支持 `&#xXXXX;` HTML 实体容错解码。

**验收标准**：`你` → `\u4f60`，且 `\u4f60` 可还原为「你」。

#### 4.3.8 图片与 Base64 互转（P2，本期仅预留）

将本地图片转为 Data URL、或将 Data URL 还原为图片预览。本期不做实现，仅在架构上预留工具位。

### 4.4 时间日期类

#### 4.4.1 日期换算（P0）★

**用户故事**：作为开发者（及泛用户），我想要查询某天的农历、星期、年内序数，以及两个日期的差值，以便做日历相关的业务开发与生活查询。

**功能要求**：

- 输入一个日期（支持 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年M月D日`），输出：
  - 星期几；
  - 农历日期（含天干地支年份与生肖）；
  - 一年中的第几天 / 第几周（ISO 周标准）；
  - 距今天数（自然日差值）；
- 日期差计算器：输入两个日期，输出相差天数；可选输出工作日天数（排除周六日，P1）；
- 「今天」快捷按钮一键填入当前日期。

**验收标准**：

- 输入 `2025-01-29` 输出农历乙巳年正月初一（蛇年）、星期三；
- 输入 `2024-01-01` 输出年内第 1 天、第 1 周（ISO）；
- 日期差：`2025-01-01` 与 `2025-03-01` 相差 59 天；
- 农历结果与权威万年历一致（抽查 1900–2100 年内 20 个随机日期）。

### 4.5 文本与生成类

#### 4.5.1 UUID 生成（P0）

**用户故事**：作为开发者，我想要批量生成 UUID，以便快速构造测试数据与主键。

**功能要求**：

- 生成 UUID v4；支持批量 1–100 个；
- 展示格式切换：标准（含连字符）、无连字符、大写；
- 一键复制全部（换行分隔）或复制单个。

**验收标准**：生成 100 个 UUID 无重复、格式合法（正则校验通过）；切格式即时生效。

#### 4.5.2 命名风格转换（P1）

**功能要求**：输入 `hello world example` 或 `helloWorldExample` 等任意风格，输出 camelCase、PascalCase、snake_case、CONSTANT_CASE、kebab-case 五种结果。

**验收标准**：`user_name` 与 `userName` 均能正确输出五种统一结果；空输入不报错。

#### 4.5.3 文本统计（P1）

**功能要求**：统计输入文本的字符数（含/不含空格）、单词数、行数、UTF-8 字节数。

**验收标准**：中英文混合文本各计数项与人工核对一致；实时随输入更新。

#### 4.5.4 二维码生成（P1）

**用户故事**：作为开发者，我想要把一段文本或 URL 生成为二维码，以便手机扫码验证跳转。

**功能要求**：

- 输入文本（≤ 1000 字符），实时生成二维码图片预览；
- 支持一键复制图片（`utools.copyImage()`）与导出 PNG；
- 纯本地生成（内置 qrcode 库），不调用外部 API。

**验收标准**：生成的二维码用 3 款主流手机扫码均可正确识别原文；URL 类型内容扫码后可直接打开。

#### 4.5.5 文本 Diff 对比（P2，本期仅预留）

左右双栏文本对比、差异高亮。本期不做实现。

### 4.6 设计辅助类

#### 4.6.1 颜色格式转换（P1）

**用户故事**：作为开发者，我想要在 HEX/RGB/HSL 之间互转颜色值，以便在代码与设计稿之间换算。

**功能要求**：

- 输入 HEX（`#1E80FF` / `#1e80ff80`）、`rgb(...)`、`hsl(...)` 任一格式，输出其余全部格式与透明度信息；
- 颜色预览色块 + 拾色器（点击弹出系统颜色选择）；
- 输出可直接使用的代码片段（CSS 变量形式）。

**验收标准**：`#1E80FF` → `rgb(30,128,255)` → `hsl(210,100%,56%)`，与设计工具换算一致；8 位 HEX 正确解析 alpha。

#### 4.6.2 单位换算（P2，本期仅预留）

长度、重量、温度、数据大小等常用单位换算。本期不做实现。

### 4.7 增值功能

#### 4.7.1 历史记录（P1）

**用户故事**：作为开发者，我想要回溯最近做过的转换内容，以便找回之前的结果。

**功能要求**：

- 每个工具自动记录最近 50 条输入（含对应输出摘要与时间），输入与上次相同则不重复记录；
- 主界面展示「最近使用」工具（按最后使用时间倒序，最多 10 个）；
- 支持单条删除与一键清空全部历史；
- 历史仅存本地（uTools 插件应用本地数据目录，不参与 uTools 云同步），不上传。

> 依据官方《数据存储》规范，「操作记录」类数据不放入同步数据库，应存储在插件应用本地数据目录（`utools.getPluginLocalDataPath()`）。

**验收标准**：使用 3 个不同工具后主界面「最近使用」按正确顺序展示；清空后本地历史文件中对应记录删除。

#### 4.7.2 工具收藏/置顶（P1）

**用户故事**：作为开发者，我想要把常用工具收藏置顶，以便呼起后第一时间使用。

**功能要求**：

- 每个工具页面与列表项提供收藏开关（星标）；
- 主界面「我的收藏」分组置顶展示，按收藏时间倒序；
- 收藏状态持久化到 `utools.db`。

**验收标准**：收藏 ≥ 3 个工具后主界面置顶分组正确展示；重启 uTools 后收藏状态保留。

#### 4.7.3 暗色模式（P1）

**功能要求**：

- 默认跟随 uTools 主题（`utools.isDarkColors()`），提供「跟随系统 / 亮色 / 暗色」三选项；
- 设置持久化到 `utools.db`。

**验收标准**：切换 uTools 深色主题后插件界面随动；手动设定后重启保持；暗色下文字对比度满足可读性（正文对比度 ≥ 4.5:1）。

#### 4.8.3 主界面与搜索框联动

进入主界面后使用 `utools.setSubInput(onChange, placeholder)` 将 uTools 搜索框主输入框接管为「工具过滤框」：`onChange` 回调实时接收输入内容用于过滤主界面工具列表，回车进入首个匹配工具后调用 `utools.removeSubInput()` 释放输入框；离开主界面恢复搜索框默认行为。需要回填内容时使用 `utools.setSubInputValue()`。

**验收标准**：主界面状态下搜索框输入「时间」仅剩时间戳/日期换算工具；回车直达；离开主界面恢复搜索框默认行为。

## 6. 技术方案考量

> 本章为实现约定，供开发阶段参考；如与实现冲突可在技术设计文档中修订。

### 6.1 技术栈

- **框架**：Vue 3（Composition API + `<script setup>`）+ Vite（沿用模板现状）；
- **语言**：JavaScript（JSConfig 项目，暂不引入 TS；类型提示依赖 `utools-api-types`）；
- **样式**：原生 CSS（`main.css` 全局变量定义主题 token），不引入 UI 组件库，保持轻量；
- **第三方库**（按需、最小化）：
  - `qrcode`：二维码生成（P1）
  - 农历算法：内置纯 JS 实现（参考开源 lunar 算法，1900–2100 覆盖）或轻量库
  - 哈希：原生 `crypto`（preload 侧）或轻量纯 JS 实现
  - Diff（P2）：`diff`

### 6.2 架构与目录规划

```
src/
├── main.js               # 入口
├── main.css              # 全局样式与主题变量
├── App.vue               # 根组件：路由分发（feature code → 工具组件）
├── router.js             # feature code ↔ 工具组件注册表（核心扩展点）
├── stores/               # 组合式状态：settings / favorites / history
├── utils/
│   ├── db.js             # utools.db 封装（收藏、历史、设置）
│   ├── clipboard.js      # 复制 + 轻提示
│   └── convert/          # 纯函数转换逻辑（与 UI 解耦，可单测）
├── components/
│   ├── ToolShell.vue     # 统一工具页骨架（标题/输入区/输出区/操作区/收藏按钮）
│   └── ...
└── tools/                # 每个工具一个目录
    ├── timestamp/index.vue
    ├── base64/index.vue
    └── ...
public/
├── plugin.json           # 入口与 features 配置（见 4.8）
├── preload.js            # 桥接层（Node 能力：哈希、文件读写等）
└── logo.png
docs/
└── PRD.md                # 本文档
```

### 6.3 uTools API 依赖清单

| API | 用途 |
| --- | --- |
| `onPluginEnter` / `onPluginOut` | 接收入口 code 分发路由；退出时清理 |
| `setSubInput` / `removeSubInput` / `setSubInputValue` | 主界面搜索框接管（4.8.3） |
| `copyText` / `copyImage` | 结果复制 |
| `dbStorage`（同步数据库键值存储） | 设置、收藏持久化 |
| `getPluginLocalDataPath()`（经 preload 桥接） | 历史记录本地文件存储 |
| `prefers-color-scheme` 媒体查询（官方推荐方式） | 暗色模式跟随 |
| `outPlugin` | 退出插件应用 |
| `setExpandHeight` | JSON 等大内容工具临时增高窗口 |

### 6.4 数据存储设计

依据官方《数据存储》规范分类：设置/收藏属于**用户数据**（适合同步数据库），历史记录属于**操作记录**（应存本地数据目录，不入同步库）。

| 存储介质 | 键 / 路径 | 内容 | 说明 |
| --- | --- | --- | --- |
| `dbStorage` | `devtools-kit:settings` | `{ theme: "auto"\|"light"\|"dark" }` | 用户设置，参与 uTools 云同步 |
| `dbStorage` | `devtools-kit:favorites` | `["timestamp", "base64", ...]` | 收藏工具 id 列表，参与云同步 |
| 本地数据目录 `history.json` | `history[toolId]` | `[{ input, output, ts }]` | 历史记录，每工具最多 50 条 LRU 淘汰，不参与云同步 |

### 6.5 路由机制

沿用模板「`onPluginEnter` 的 `action.code` → 切换视图」模式，抽象为注册表 `router.js`：每个工具注册 `{ code, component, cmds }`；主界面（`devtools-kit` code）作为特殊路由渲染工具导航页。工具间跳转（如从主界面进入某工具）通过内部状态切换，不再触发 `onPluginEnter`。

## 7. UI/UX 设计要求

- **布局**：单栏垂直流（输入区在上、结果区在下、操作按钮常驻右侧或底部），适配 800×544 初始窗口，窗口拉伸时自适应；
- **风格**：简洁工具风，参照 uTools 官方审美：紧凑行距、中性色为主、品牌色点缀；
- **字体**：输入/输出区使用等宽字体（如 `JetBrains Mono, Consolas, monospace`）保证对齐；
- **主题**：CSS 变量定义 `--bg`/`--fg`/`--accent` 等 token，暗色模式仅切换变量值；
- **可访问性**：按钮均有文字或 icon+tooltip；错误信息与输入框关联（`aria-describedby`）；
- **反馈**：所有成功操作（复制/收藏/清空）均有 ≤ 1.5s 的轻提示，不打断操作。
